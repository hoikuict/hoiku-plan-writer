# 安全計画作成支援機能 仕様書

対象機能: 安全計画ウィザード / 安全計画自動生成 / 実施ログ / 減算リスク確認 / 出力

版数: 0.2（ドラフト）

作成日: 2026年5月18日

## 0. 前提

依頼は「対話的に項目を埋めれば施設に合った安全計画が自動生成され、減算対象とならないようにする」というものだが、制度要件上、計画を自動生成するだけでは減算回避として不十分である。

こども家庭庁資料によれば、減算は主に次の状態を対象とする。

- 安全計画を策定していない
- 計画に定めた内容が実施されていない状態が1年継続している

保育所・地域型保育事業所では、実施状態は「訓練・研修の実施」「保護者等への周知」「安全計画の見直し」の項目ごとに、最後の実施日から1年のローリングで判定される。したがって本機能の中核は、計画生成だけでなく、実施状況の継続トラッキング、証跡管理、期限アラートにある。

令和8年（2026年）7月から減算が適用されるため、未策定施設にとっては導入時点で時間的余裕が小さい。MVPでは、短時間で策定し、そのまま実施管理に入れる導線を優先する。

## 1. 目的

- 児童福祉施設の設備及び運営に関する基準第6条の3、及び幼稚園・認定こども園に係る学校保健安全法第27条に基づく安全計画を、施設の実態に合わせて低負荷で策定できるようにする。
- 策定後の研修・訓練、保護者周知、計画見直しを期限管理し、令和8年7月からの「安全計画の策定等をしていない場合」の減算リスクを低減する。
- 指導・監査時に、計画を策定し、計画に従って必要な措置を講じていることを説明できる記録を残す。

## 2. 対象範囲

### 2.1 MVP対象

- 施設種別: 幼稚園、保育所、認定こども園、家庭的保育事業所、小規模保育事業所、事業所内保育事業所、居宅訪問型保育事業所
- 主利用者: 園管理者、施設長、主任、事務担当
- 補助利用者: 担任、クラス担当
- 対象文書: 年度単位の安全計画
- 対象管理: 計画本文、年間実施予定、マニュアル、点検チェックリスト、実施ログ、見直しログ、保護者周知ログ、減算リスク確認

施設類型により根拠条文と減算判定単位が異なるため、施設種別をプロファイルの第一項目とし、画面文言、生成内容、判定ロジックを分岐する。

### 2.2 対象外

- 自治体への計画提出や電子申請の代行
- 給付費の会計処理、請求連携
- 事故報告書そのものの作成
- 園児個人単位の健康情報、アレルギー詳細、障害情報の管理
- 添付ファイル本文のAI解析
- 自治体独自様式の完全再現
- 法令解釈の確定的判断

本機能の出力は計画策定と運用管理の補助であり、最終的な適合判断は施設及び管轄自治体が行う。

## 3. 制度要件

### 3.1 安全計画の策定義務

保育所等は、児童の安全を確保するための取組を計画的に実施する安全計画を策定する必要がある。

安全計画には、少なくとも次の事項を含める。

- 施設・設備の安全点検
- 施設外活動を含む日常生活における児童・職員への安全指導
- 職員の研修及び訓練
- その他、施設における安全に関する事項

施設長等は、策定した安全計画を職員に周知し、研修・訓練を定期的に実施する。保育所及び児童発達支援センターは、保護者に対して安全計画に基づく取組内容等を周知する。安全計画は定期的に見直し、必要に応じて変更する。

### 3.2 計画に必須の構成要素

こども家庭庁「保育所等における安全計画の策定に関する留意事項等について」は、計画に盛り込むべき取組を次の4区分で示している。生成ロジックはこの4区分を必須セクションとする。

1. 安全点検
   施設・設備、備品、遊具、防火設備、避難経路、散歩コース、公園等を定期的に点検し、文書として記録し、改善点を改善する。通常保育時、午睡、食事、プール・水遊び、園外活動、バス送迎、災害、不審者侵入、火災・119番通報等の役割分担を明確にし、常勤職員だけでなく非常勤職員・保育補助者にも共有する。

2. 児童・保護者への安全指導等
   発達や能力に応じて、児童が安全や危険を認識し、災害や事故発生時の約束事や行動を理解できるようにする。交通安全を学ぶ機会を設け、保護者に安全計画と園の取組を説明・共有し、家庭での安全教育も依頼する。

3. 実践的な訓練・研修
   地震・火災だけでなく地域特性に応じた災害を想定した避難訓練、救急対応、心肺蘇生、気道内異物除去、AED、エピペン、不審者侵入、119番通報訓練を行う。自治体研修やオンライン研修も含め、非常勤職員を含む全職員の受講を管理する。

4. 再発防止
   ヒヤリ・ハットを収集し、要因分析と対策を行う。事故が発生した場合は、原因分析と再発防止策を講じ、点検箇所やマニュアルに反映し、職員間で共有する。

### 3.3 減算の仕組み

令和8年7月から、対象施設で安全計画の策定又は実施をしていない場合の減算が創設される。減算額は月額1,350円。

- 未策定の場合: 策定された日の属する月まで減算対象となる。
- 計画内容を実施していない場合: その状態が1年継続した日の翌月から、状態が解消した日の属する月まで減算対象となる。

計画があっても、内容が著しく不足している場合は「策定している」要件を満たさない扱いになり得る。特に、訓練・研修の計画がない計画は高リスクとする。

### 3.4 施設類型別の判定単位

| 項目 | 保育所 / 家庭的保育 / 小規模保育 / 事業所内保育 / 居宅訪問型保育 | 幼稚園 / 認定こども園 |
| --- | --- | --- |
| 根拠 | 児童福祉施設の設備運営基準第6条の3、家庭的保育事業等の設備運営基準 | 学校保健安全法第27条及び同条準用 |
| 減算判定単位 | 研修・訓練、保護者周知、見直しを項目別に1年クロックで判定 | 計画に定める取組を全体で1年クロックとして判定 |
| トラッキング軸 | `training_drill`, `parent_notice`, `review` | `school_safety_action` |
| 画面文言 | 安全計画 | 学校安全計画 |
| 居宅訪問型の留意 | 訪問先の室内環境、非常口、避難経路確認、職員研修、保護者周知を重視 | 対象外 |

## 4. 設計方針

1. 事務負担を増やさない
   既存の園プロファイル、年間行事、地域資源、健康・安全方針を初期値として流用する。入力は選択式を中心にし、自由記述は必要最小限にする。

2. 施設の実情に合わせる
   バス送迎、プール・水遊び、午睡、給食、園外活動、地域災害、積雪、津波、土砂災害、熱中症、鳥獣被害など、該当するリスクだけを計画に反映する。

3. 減算回避に必要な運用まで扱う
   計画本文だけでなく、研修・訓練、保護者周知、見直しの最終実施日を管理し、1年未実施に近づく前に警告する。

4. AIは不足を埋めない
   未入力や施設固有情報が不明な場合、AIは推測で決めず「要確認」とする。証跡ログも自動捏造しない。

5. 決定的ロジックを優先する
   必須要素の有無判定、期限計算、減算リスク表示はLLMに委ねず、ルールベースで実装する。LLMは文案整形や施設特性に応じた表現補助に限定する。

6. 根拠を表示する
   生成された各ブロックに、［園方針］［入力］［公的根拠］［AI構成］の由来タグを付ける。

## 6. 機能要件

### F-1 施設プロファイル

| 項目 | 内容 | 用途 |
| --- | --- | --- |
| 施設類型 | 7類型から選択 | 根拠条文・減算判定単位の分岐 |
| 施設名・所在地・代表者 | 文字列 | 計画ヘッダ |
| 自治体 | 都道府県 / 市区町村 | 自治体固有様式・連絡先の注記 |
| 定員・年齢構成 | 0歳から就学前の区分別 | 年齢別チェックリスト、午睡・食事リスクの調整 |
| 送迎バス有無 | 有 / 無 | バス送迎の点呼、安全装置、見落とし防止項目の要否 |
| 散歩・園外活動 | 有 / 無、主要ルート | 園外点検、散歩計画項目の要否 |
| プール・水遊び | 有 / 無 | 水遊びリスク項目 |
| 給食・調理室 | 有 / 無、アレルギー対応 | 食事リスク、救急対応研修 |
| 立地リスク | 地震、風水害、土砂、津波、火山、原子力等 | 避難訓練の想定災害 |
| 職員数・常勤/非常勤 | 人数 | 研修対象者の全職員カバー確認 |

プロファイルは園プロファイルから初期化し、年度更新では前年度から引き継いで変更点だけ確認する。

### F-2 対話型ヒアリング

- 4必須区分に沿って、原則として「はい/いいえ」「複数選択」「月選択」で質問する。
- プロファイルから自明な質問はスキップする。例: 送迎バスなしの場合、バス関連設問を必須化しない。
- 各質問にデフォルト回答を用意し、空回答でも計画案が成立するようにする。
- 1セッションを中断・再開できる。
- 新規策定は20から30分、年度更新は5から10分を目標にする。

### F-3 安全計画の自動生成

安全計画は、全文テキストではなく `GeneratedPlan` / `SectionBlock` と同じ思想でブロック構造として保持する。

| section_key | 見出し | 必須 | 内容 |
| --- | --- | --- | --- |
| safety_basic_policy | 基本方針 | 必須 | 児童の安全確保、計画の対象範囲、年度、根拠 |
| safety_facility_profile | 施設・地域の特徴 | 必須 | 施設設備、園外活動先、地域災害、交通環境 |
| safety_annual_schedule | 年間スケジュール | 必須 | 月別の点検・研修・訓練・周知・見直し |
| safety_inspection | 施設・設備等の安全点検 | 必須 | 園舎、遊具、防火設備、避難経路、散歩コース、公園 |
| safety_manuals | マニュアル・役割分担 | 必須 | 午睡、食事、プール、園外活動、災害、不審者、バス等 |
| safety_child_guidance | 児童への安全指導 | 必須 | 発達に応じた交通安全、防災、防犯、生活安全 |
| safety_staff_training | 職員研修・訓練 | 必須 | 避難、救急対応、119番通報、不審者、事故予防 |
| safety_parent_notice | 保護者への周知・連携 | 必須 | 周知時期、方法、家庭での安全教育依頼 |
| safety_incident_prevention | 事故・ヒヤリ・ハット再発防止 | 必須 | 収集、分析、再発防止、計画・マニュアル反映 |
| safety_review | 見直し・改訂 | 必須 | 定期見直し、変更なし判断の記録、承認 |
| safety_evidence | 証跡管理 | 必須 | 保存する記録、保管場所、確認方法 |

必須ブロックが欠ける場合、承認状態を「要確認」にし、減算リスクチェックで「計画内容不足」と表示する。

### F-4 付随マニュアルとチェックリスト生成

安全計画の実効性を担保するため、計画と整合した最小マニュアルを併せて生成する。

- リスク場面別マニュアル: 午睡、食事、プール・水遊び、園外活動、バス送迎
- 緊急時マニュアル: 災害、不審者侵入、火災、119番通報、保護者連絡
- 年齢別安全点検チェックリスト
- 園外活動チェックリスト: 目的地、経路、危険箇所、引率体制、緊急連絡方法
- 居宅訪問型向けチェックリスト: 訪問先の室内環境、非常口、避難経路

### F-5 コンプライアンスチェック

- 第1項相当: 必須4区分と必須ブロックが計画に存在するかを判定する。
- 保育所・地域型: 研修・訓練、保護者周知、見直しの最終実施日から1年以内かを判定する。
- 幼稚園・認定こども園: 学校安全計画に定める取組の最終実施日から1年以内かを判定する。
- 証跡メモ、添付、参加記録の有無を確認し、監査で説明しにくい項目を注意表示する。
- 結果は「適合」と断定せず、リスク区分と根拠を提示する。

### F-6 実施トラッキング・期限アラート

減算対象アクションを施設類型別に定義する。

| 施設類型 | アクション | 判定 |
| --- | --- | --- |
| 保育所・地域型 | `training_drill` | 研修・訓練の最終実施日から1年 |
| 保育所・地域型 | `parent_notice` | 保護者周知の最終実施日から1年 |
| 保育所・地域型 | `review` | 見直しの最終実施日から1年 |
| 幼稚園・認定こども園 | `school_safety_action` | 計画に定める取組の最終実施日から1年 |

実施記録には、実施日、種別、対象者、参加者、担当者、方法、証跡メモ、添付ファイル又は保管場所、備考を持たせる。

期限算出は `次回期限 = 最終実施日 + 1年` とする。令和8年7月より前に1年未実施となっている場合は、令和8年7月からリスクありとして表示する。アラートは90日前、30日前、7日前、超過後に出す。MVPではアプリ内通知を必須とし、メール等は将来拡張とする。

### F-7 見直し支援

- 年度内の見直しイベントを管理する。
- 見直しログを登録すると、保育所・地域型の `review` クロックを更新する。
- 見直し結果が「変更なし」の場合も、検討日、参加者、判断理由、議事メモを保存し、証跡として扱う。
- ヒヤリ・ハットや事故の登録から、点検箇所・マニュアルへの反映タスクを生成する。

### F-8 周知・記録管理

- 職員周知: 計画・マニュアルの配布、閲覧、説明会、研修受講を記録する。
- 保護者周知: 入園時説明、掲示、園だより、保護者アプリ配信、公表を記録する。
- 証跡保存: 計画、点検記録、研修・訓練記録、周知記録、見直し記録を年度単位で保管する。
- 保存期間は最低3年を既定値とし、自治体要件に応じて設定で延長できるようにする。

### F-9 出力

- 印刷用HTML
- PDF
- Word（将来拡張、施設側が自治体提出様式に合わせて編集できる形式）
- 計画本体、マニュアル、チェックリスト、実施記録、自己申告チェックリストを個別又は一括で出力する。
- 過去年度版をアーカイブし、年度更新時に差分閲覧できるようにする。

## 7. 作成ウィザード仕様

### 7.1 ステップ構成

| ステップ | 入力内容 | 入力負荷軽減 |
| --- | --- | --- |
| 1. 基本情報 | 年度、施設種別、対象年齢、利用定員、開所形態、作成責任者 | 園プロファイルから初期表示 |
| 2. 施設・地域リスク | 建物階層、園庭、散歩コース、近隣公園、交通量、水辺、災害想定 | チェックボックスと自由追記 |
| 3. 活動リスク | 午睡、食事、アレルギー対応、水遊び、園外活動、バス送迎、延長保育 | 該当あり/なしで分岐 |
| 4. 安全点検 | 点検対象、頻度、記録方法、改善管理 | 標準項目を全選択で開始 |
| 5. 役割分担 | 施設長、主任、各クラス、送迎担当、給食担当、連絡担当 | 役割名だけでも可 |
| 6. 安全指導・周知 | 児童への指導、保護者周知、家庭への依頼 | 入園時・年度初め等を初期配置 |
| 7. 訓練・研修 | 避難、救急、不審者、119番通報、バス見落とし防止 | 施設リスクに応じて候補提示 |
| 8. 再発防止 | ヒヤリ・ハット収集、分析、共有、反映 | 月次会議での確認を初期値 |
| 9. 生成確認 | 未入力、要確認、減算要件不足を確認 | 不足項目を1画面で修正 |

### 7.2 標準テンプレート

施設種別とリスク選択に応じて、標準予定を自動挿入する。

- 4月: 年度初めの安全計画確認、職員周知、保護者周知、散歩コース確認
- 5月: 不審者対応又は通報訓練、交通安全指導
- 6月: 水遊び・プール前のマニュアル再周知、熱中症対策確認
- 7月から8月: 熱中症、食中毒、水遊び、午睡確認
- 9月: 防災訓練、引き渡し訓練、台風・風水害対応確認
- 10月から11月: 園外活動・遠足前確認、感染症流行期前確認
- 12月から1月: 冬季災害、積雪地域は雪害対応確認
- 2月: 年度見直し検討、次年度安全計画への反映
- 3月: 新年度職員周知準備、入園説明向け周知準備
- 随時: 新規採用職員研修、入園時保護者周知、事故・ヒヤリ・ハット発生時の再発防止反映

年度更新では、前年度計画を複製し、職員異動、新規リスク、前年の事故・ヒヤリ・ハット反映だけを確認する短縮フローを用意する。

## 8. 減算リスク判定仕様

### 8.1 ステータス

| ステータス | 条件 | 表示 |
| --- | --- | --- |
| compliant | 必須計画ブロックがあり、施設種別ごとの最終実施日が期限内 | 充足 |
| attention | 期限まで60日以内、又は証跡メモが薄い | 期限注意 |
| warning | 期限まで30日以内、又は必須証跡が不足 | 要対応 |
| high_risk | 未策定、内容著しく不足、又は1年未実施状態 | 減算リスク |
| unknown | 初期データ不足で判定不可 | 要確認 |

### 8.2 減算開始月の推定

アプリは法的確定ではなく「推定」として表示する。

- 未策定: 令和8年7月以降、策定日の属する月までリスクあり
- 実施未了: 最後の実施日の翌日から1年を満了した日の翌月からリスクあり
- 令和8年7月より前に1年未実施となっている場合: 令和8年7月からリスクあり
- 解消ログがある場合: 解消日の属する月までリスク期間として表示

判定結果には「自治体の確認方法に従って最終判断してください」と表示する。

### 8.3 自己申告チェックリスト

年度ごとに次のチェックリストを生成する。

- 安全計画又は学校安全計画を策定済みである
- 計画に施設・設備点検を含む
- 計画に安全指導を含む
- 計画に職員研修・訓練を含む
- 研修・訓練を1年以内に実施し、記録がある
- 保護者周知を1年以内に実施し、控えがある
- 見直しを1年以内に実施、又は検討記録がある
- 幼稚園・認定こども園では、学校安全計画に定める取組を1年以内に実施している
- 事故・ヒヤリ・ハットを必要に応じて計画やマニュアルに反映している

### 9.2 既存モデルとの関係

- `NurseryProfile` の `health_and_safety_policy`, `local_context`, `community_resources`, `family_collaboration_policy`, `local_collaboration_policy` を初期値に使う。
- `GeneratedPlan` / `SectionBlock` の構造を流用し、安全計画もブロック編集・根拠タグ表示に対応する。
- `ApprovalLogRecord` と同等の承認履歴を安全計画にも持たせる。
- 将来的に `PlanDocumentRecord.document_type = safety` として統合するか、監査ログの粒度を優先して専用テーブルを持つかは実装時に決める。MVPでは実施ログが重要なため専用テーブルを推奨する。
- `SafetyImplementationLog` と `SafetyComplianceSnapshot` を減算判定の単一の真実源とする。計画上の予定と実績は別管理し、判定時に突合する。

## 10. AI仕様

### 10.1 入力ソース

- 園プロファイル
- 施設プロファイル
- 安全計画ウィザード入力
- 公的根拠パック
- 既存の年間指導計画や年間行事予定
- 前年度安全計画と実施ログ

### 10.2 生成ルール

| ID | ルール | 内容 |
| --- | --- | --- |
| SAF-AI-01 | 不足補完禁止 | 施設固有の危険箇所や実施済み証跡を推測で埋めない |
| SAF-AI-02 | 該当リスクのみ出力 | バス送迎なしの施設にバス運行計画を必須扱いで出さない |
| SAF-AI-03 | 必須事項保持 | 点検、安全指導、研修・訓練、保護者周知、見直しを必ず含める |
| SAF-AI-04 | 年間予定化 | 「いつ、何をするか」が分かる月別予定にする |
| SAF-AI-05 | 証跡欄生成 | 各取組に記録方法と保管場所を付ける |
| SAF-AI-06 | 園らしさ反映 | 園プロファイルの理念、地域性、保育観を本文に反映する |
| SAF-AI-07 | 高リスク場面明示 | 午睡、食事、プール・水遊び、園外活動、バス送迎等を該当時に明示する |
| SAF-AI-08 | 表現制約 | 法令遵守を断定しすぎず、確認が必要な箇所は「要確認」にする |
| SAF-AI-09 | 判定非委譲 | 適合性判定、期限計算、減算リスク算出はLLMで行わない |

## 12. 非機能要件

- 事務負荷軽減: 新規策定20から30分以内、年度更新10分以内を目標にする。
- 保守性: 法令・様式改正時にテンプレート、判定ルール、施行日、減算額、クロック年数を設定で差し替えられるようにする。
- セキュリティ: アクセス制御、監査ログ、保存データ保護を行う。計画本体に園児個人を特定できる情報を含めない。
- 記録の完全性: 実施ログは追記型を基本とし、削除・改変は監査ログに残す。
- アクセシビリティ: PC・タブレット対応。専門語には補足説明を付ける。

## 13. 受入基準

| ID | 受入条件 | 判定方法 |
| --- | --- | --- |
| SAF-AC-01 | 園プロファイルをもとに安全計画ウィザードの初期値が表示される | 既存プロファイル保存後に作成画面で確認 |
| SAF-AC-02 | 施設類型により、保育所向け安全計画と幼稚園向け学校安全計画の文言・判定軸が分岐する | 施設類型を切り替えて確認 |
| SAF-AC-03 | 必須ブロックを含む年度安全計画が生成される | 生成結果に11ブロックがあることを確認 |
| SAF-AC-04 | バス、プール、積雪等の非該当リスクは必須化されない | チェックなしで生成し、要確認に出ないことを確認 |
| SAF-AC-05 | 研修・訓練、保護者周知、見直しの最終実施日が個別に表示される | 保育所類型で実施ログ登録後のダッシュボードを確認 |
| SAF-AC-06 | 学校安全計画に基づく取組の最終実施日が表示される | 幼稚園・認定こども園類型で確認 |
| SAF-AC-07 | 1年未実施に近づくと注意・警告が出る | 日付を固定したユニットテストで確認 |
| SAF-AC-08 | 計画内容が不足する場合、承認前に減算リスクとして表示される | 必須ブロック欠落ケースで確認 |
| SAF-AC-09 | 見直し結果が「変更なし」でも検討記録として保存できる | 見直しログで `changed=false` を保存 |
| SAF-AC-10 | 自己申告チェックリストを年度単位で出力できる | 印刷表示で確認 |
| SAF-AC-11 | AI生成時、未入力の施設固有情報を推測で埋めない | 欠落入力テストで「要確認」を確認 |
| SAF-AC-12 | 証跡ログを捏造せず、未登録は未登録として扱う | 実施ログなしの状態でリスク判定を確認 |

## 14. 実装フェーズ

### Phase 1: ルールベースMVP

- 施設プロファイル
- 安全計画作成ウィザード
- ルールベース生成
- ブロック編集、保存、承認
- 実施ログ登録
- 減算リスク判定
- 印刷表示

### Phase 2: 証跡・PDCA

- 付随マニュアル生成
- チェックリスト生成
- ヒヤリ・ハット反映タスク
- 周知記録
- 自己申告チェックリスト
- PDF出力

### Phase 3: AIプレビュー・年度更新

- LLMによる計画文案の自然な文案化
- 園プロファイルとの整合レビュー
- 必須事項不足レビュー
- 前年度計画からの更新案生成
- Word出力
- 自治体別チェックリスト設定

優先順は、生成機能の直後に実施トラッキング・期限アラートを実装する。F-6を後回しにすると、依頼の主目的である減算リスク低減が満たされないためである。

## 15. 未確定事項

- 自治体ごとの提出様式・提出経路
- 監査での記録参照期間
- 「計画に定める内容の実施」と判定される具体的範囲
- 居宅訪問型など施設類型別の細かな運用
- 認可外保育施設への拡張要否

これらは管轄自治体への確認、又は追加通知の確認が必要である。本機能は確定情報を設定で差し替えられる構造とする。
