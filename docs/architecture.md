# 初期アーキテクチャ

## 目的

MVP 仕様書の主要ユースケースをすぐ実装し始められるように、まずは UI より先にドメインと生成結果の構造を固定する。

## レイヤー

- `domain`
  仕様に出てくるエンティティ、列挙型、構造化ブロックを保持する。
- `services`
  年間指導計画と月案の生成ロジック、シリアライズ、将来の AI 連携差し替えポイントを置く。
- `cli`
  ローカルでサンプル出力を確認するための暫定入口。

## 設計方針

- 生成結果は段落単位で編集できるよう `SectionBlock` の配列で保持する
- 必須入力が欠けた場合は推測せず `要確認` を返す
- 月案は年間指導計画の該当期を参照して一貫性を保つ
- UI 未決定でも進められるよう、入出力は Python オブジェクト中心にする

## 次フェーズ

- 永続化層の追加
- 承認履歴と版管理
- Web フォーム UI
- AI プロンプト層とレビュー UI
